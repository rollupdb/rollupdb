# Quantile sketches and measured accuracy

Session 3 uses the generic float64 KLL implementation in Apache DataSketches Go v0.2.0. KLL is compact and mergeable and has an explicit normalized-rank error model. This is a distribution summary, not a list of already-computed p50/p95/p99 answers. Observations accepted by exact-state validation are added to both representations; rejected observations affect neither. Sketch state, exact state, counters and the watermark commit together.

New stream definitions may include the following immutable configuration:

```json
"sketch": {"algorithm":"kll_float64","encoding_version":1,"k":200,"m":8}
```

The first supported codec requires the displayed algorithm and encoding version, fixed M=8 and K from 64 through 4096. There are no hidden sketch defaults. Larger K usually trades more retained state for a smaller rank error. Working batch memory also grows with touched bucket count and K; exported size is not a memory-usage bound. Only identical configurations may be merged in this prototype. Although upstream supports some mixed-K cases, this codec refuses them rather than silently weakening its error model. Definition version 1 remains immutable; to begin collecting a distribution for an exact-only stream, create a new sketch-enabled stream. Migration cannot recover distributions from old counts, sums or moments.

## Query contract

Add quantiles such as [0,0.5,0.95,0.99,1] to the existing Query or its CLI JSON file. These are normalized ranks, so p99 is 0.99. At most 32 finite distinct ranks in [0,1] are accepted. The response preserves request order and returns rank, nullable value and approximate for each answer. Rank 0 and 1 are exact preserved extrema. Other answers use the upstream inclusive nearest-rank convention: ceil(rank*N), with its documented 1e-7 natural-rank rounding when N<=1e7, then a zero-based index clamped at the minimum. No interpolation between adjacent observation values is performed.

quantile_accuracy reports availability, algorithm, encoding_version, K, M, normalized_rank_error, error_model, retained_items and estimation_mode. Exact retained distributions report rank error zero. Estimated distributions report the library's single-sided normalized-rank error and the error_model label empirical_99_percent_max_rank_error. At K=200 this model is approximately 0.0132947575, or 1.3295 percentage points of normalized rank. This is a fitted 99%-confidence empirical maximum-error model, not a deterministic ceiling, an accuracy claim verified by one experiment, or a relative value-error guarantee.

Exact-only streams return null percentile values and availability=not_retained. A configured stream with no collected history returns not_collected; a covered empty interval returns no_observations. Neither becomes a zero-valued percentile. A configured populated bucket with missing or incompatible bytes returns ErrSketchEncoding. Queries asking only for exact statistics do not need to deserialize optional sketch payloads, while percentile queries validate every matched sketch. Unknown definition-level sketch types/settings fail validation.

The upstream implementation randomly compacts during updates and some merges. RollupDB does not reseed a global random generator or enable upstream private test behavior. A single persisted bucket is decoded and queried directly, so its estimates survive ordinary restart and snapshot/copy/reopen identically. A query across multiple buckets can recompact while merging and produce slightly different estimates on repeated reads, including after restart; its exact statistics remain unchanged. Serialization of an unchanged individual sketch is stable in round-trip tests, but independent builds or merged query sketches need not have identical samples or bytes.

## Guarded storage

Format revision 3 adds a nullable BLOB sketch column to buckets. Existing exact-only rows remain null. The RollupDB envelope is 48 bytes followed by the upstream compact payload. Bytes 0..3 are RDKL; byte 4 is envelope version 1; byte 5 is the float64-KLL type ID 1; bytes 6..7 encode little-endian K; byte 8 is M; bytes 9..11 are zero; bytes 12..15 encode payload length; bytes 16..47 are SHA-256 of the payload. Configuration must match the immutable definition exactly. This checksum detects accidental damage; it is not authentication against an editor who can recompute it.

Before calling the pinned deserializer, the adapter checks envelope size and checksum, native family and compact encoding version, permitted flags, K/M/minK, bounded level count and capacity, exact byte length, monotone level indices, checked weighted observation count, finite retained values, sorted higher levels and exact extrema. Native single-item and full compact encodings are supported; empty payloads are not valid for populated buckets. Payloads are capped at 4 MiB and 63 levels. compactCapacity adapts the pinned serializer's integer rounding solely to validate layout safely; update and compaction algorithms remain upstream. Unknown encodings, excessive allocations and corrupt indices are rejected before entering a deserializer that assumes well-formed input. A recovery boundary also converts unexpected parser panics to errors.

Tests cover K=64,200,4096 across exact and estimation sizes, count and endpoint consistency, decoded updates, unknown envelope/native versions, parameter mismatch, checksum damage, truncation, level overflow, invalid counts and nonfinite values. Database tests verify failed decoding cannot update buckets, counters or watermarks. A ten-second, two-worker fuzz run exercised malformed native payloads after recomputing their outer checksums and completed without a failure. The guarded codec still requires explicit compatibility review when changing the upstream version.

## Reproducible inputs and measured results

Run go run ./examples/accuracy -n 100000 to regenerate the experiment. Inputs are deterministic, while KLL sampling and therefore the measured estimates vary. The recorded run is docs/accuracy-session-3.json: five datasets (uniform, skewed, heavy-tail, duplicates and constant), each with 100,000 observations, in direct and seven-bucket layouts. Each stream has one dimension group. This is one million ingestion operations across ten cases; it is not a representative benchmark of arbitrary telemetry cardinality or historical retention.

The recorded serialized input sizes were 7,300,000–8,947,160 bytes. Direct-case snapshots were 49,152 bytes; seven-bucket snapshots were 73,728 bytes. Raw-input-to-snapshot ratios ranged from approximately 99:1 to 182:1. These are lossy aggregation savings for explicitly declared, short histories. They exclude live WAL bytes, peak export space and the experiment's sorted-reference memory. Automatic coarsening and expiry were not run. More groups, longer fine-resolution histories or larger K change the outcome.

For the requested ranks 0,0.5,0.9,0.95,0.99,1, the largest recorded duplicate-aware rank discrepancy was 0.00351 (0.351 percentage points), below that run's 0.0132947575 empirical model. The report places individual rank and value errors next to each case's size saving. It does not estimate a 99% success probability from these few cases. In one heavy-tail partitioned case, p99 had only 0.00181 normalized-rank discrepancy but about 28.29% relative value error, illustrating why rank accuracy must not be advertised as value accuracy. Constants and the tested duplicate-heavy fixture had zero observed error at the requested ranks.

The independent reference sorts original values outside the database. For a returned value v, it computes the true rank interval [count(x<v)/N,count(x<=v)/N]; rank error is the distance from the requested rank to that interval. This handles ties without inventing a midpoint error. Absolute value error compares the returned value with the convention-matched exact nearest-rank value. Relative value error is null when the exact reference is zero. Regression tests use a conservative four-times-model rank ceiling plus one observation of discreteness, rather than turning a stochastic 99% model into a flaky deterministic assertion. These tests catch gross regressions but do not establish a confidence guarantee.
