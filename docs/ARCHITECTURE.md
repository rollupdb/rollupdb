# Architecture and storage decision

Status: RollupDB 0.1. Embedded engine, CLI, local HTTP service and measured-history example.

RollupDB retains declared information about observations, rather than retaining the observations themselves. A stream defines one scalar numeric value, event time, a joint set of dimensions, supported statistics and a retention policy. Statistics must carry sufficient mergeable state to survive multiple levels of aggregation. Storage reduction depends on retained groups, time buckets and sketch parameters; it is not a guaranteed ratio of raw bytes.

## Storage decision: SQLite, pure Go

The first implementation uses `database/sql` and `modernc.org/sqlite v1.60.1`, with `modernc.org/libc` resolved at the exact version required by that driver. WAL plus `synchronous=FULL` provides the intended transactional base. One connection and a handle-level mutex serialize driver access and lifecycle operations. A five-second SQLite busy timeout bounds ordinary external lock waits; callers should use context deadlines. Waiting for the Go handle mutex is not currently context-aware.

The choice avoids building a page allocator, transaction log, locking scheme and crash-recovery protocol merely to demonstrate aggregate retention. It comes with a sizeable transitive dependency graph and initial compilation cost; those are accepted prototype tradeoffs. A custom file engine is deferred until a measured requirement justifies it. No claim of lower overhead than RRDtool is made.

The supported portable object is a successful `VACUUM INTO` snapshot. The code reserves a new destination with owner-only permissions, binds its path as SQL data, performs export, and explicitly syncs the resulting file. It refuses overwrite. This produces a compact consistent snapshot without copying the source WAL. It is not atomic publication: incomplete output may survive process termination, and parent-directory syncing is not implemented. Those limits are explicit rather than hidden behind a portability claim.

SQLite identity is checked before persistent journal settings are changed. A database with a different application ID or unsupported schema version is rejected. `Open` never silently creates a database. `Create` never adopts an existing file. External SQL edits are unsupported even though the file is SQLite-readable.

## Boundaries

The root package owns lifecycle, metadata, stream definitions, exact statistical state, ingestion, retention, mixed-resolution queries and snapshot export. Statistical arithmetic is isolated in state.go. A batch caches touched buckets in memory and flushes their final state in one transaction, rather than updating a row for every observation. Dimension group admission follows input order, and queries merge in stable bucket/key order. The CLI and transport package adapt bounded input to that package. Streaming imports retain only bounded pending batches and emit post-commit receipts; failures preserve earlier commits and describe the pending/unacknowledged suffix.

Format revision 2 added exact buckets, dimension groups and per-definition runtime metadata. Revision 3 adds nullable, checksummed sketch payloads, leaving old exact-only rows without a distribution. Revision 4 adds contiguous tier frontiers; migration from revisions 1, 2 or 3 is explicit and transactional. A persisted nondecreasing watermark prevents a backward clock jump from reopening a closed ingestion window. No raw-event table is created. Recorded coverage begins at the first batch's earliest admissible bucket and extends through its committed watermark; it describes the recorder, not completeness of an upstream telemetry feed.

KLL state is isolated behind sketch.go and bounded format validation in kll_format.go. Apache DataSketches Go v0.2.0 supplies the algorithm. Equal configurations merge; unknown or mismatched state fails before writes. Percentile queries decode only matched buckets and use the first persisted sketch directly, merging additional buckets as needed. Random merge compaction can change approximate point answers while retaining the declared rank-error model. retention.go implements explicit whole-parent promotion, final expiry and key reclamation in one transaction. Query ownership bands derive from persisted frontiers and remain disjoint even over empty time ranges. Operations never run implicitly on reads or ingestion.

Transport must not implement its own aggregation logic. CLI and eventual HTTP requests must call the same embedded ingestion/query operations. No cloud service is necessary. The HTTP service now binds only to literal loopback IPs, applies bounded strict JSON and server/request timeouts, refuses browser Origin/nonlocal Host requests, and exports snapshots via private temporary files. It has no authentication or remote-hosting mode. Its owner closes the handle only after shutdown. See docs/INTERFACES.md.

The first prototype does not offer concurrent independent owners, hosted multi-tenancy, SQL, event deduplication, raw-event retention/search, clustering, arbitrary historical regrouping or calendar-month buckets. All of those increase semantics and maintenance surface without proving the core product.

## Validation strategy

The tests cover storage identity, invalid-file refusal, immutable stream creation, reopen, live snapshots, overwrite refusal and concurrency. An independent rational reference checks weighted arithmetic, overflow, grace, rollback, dimensions, availability and migration. Quantile tests add independent sorted-reference measurement, direct/partitioned accuracy, codec and parameter rejection, malformed-payload fuzzing, decoded updates, old-data non-backfill, single-sketch snapshot stability and multi-bucket filtered queries. Measured fixtures report value/rank error alongside exported size. Retention tests inject SQL failures at parent insertion, source deletion, frontier writing, key reclamation and watermark writing, then verifies complete rollback and safe retries. Tests cross retained resolutions, sparse years, expiry and restart boundaries. Process-kill tests (the crash_*_test.go files) kill the owning process during acknowledged ingestion, open transactions, a finished promotion and an Advance just before commit, then reopen and check that exactly the acknowledged state survived. Physical power loss is not tested. Transport tests add input/output failure, partial-progress, byte-boundary, malformed/body-limit, endpoint equivalence, snapshot download and real-listener shutdown tests. The history example reads source NDJSON outside the engine and uses integer sums plus rational variance and sorted rank references. Cross compilation checks build portability; native CI is required to validate platform behavior.

Primary references consulted for the storage spike: https://pkg.go.dev/modernc.org/sqlite@v1.60.1 , https://www.sqlite.org/lang_vacuum.html , https://www.sqlite.org/backup.html . Driver behavior is tested against the pinned dependency rather than inferred from an unpinned latest release.
