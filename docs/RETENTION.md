# Explicit retention and mixed resolutions

The caller runs `db.Advance(ctx, stream)` or `rollupdb advance FILE STREAM`. There is no implicit scheduling on ingestion or reads. A successful call commits all promotions, source deletions, final expiry, unreferenced-group reclamation, contiguous frontiers and a nondecreasing watermark together. A retry at the same time does not remerge sources. Batch ingestion still accepts events only into open finest-tier buckets, even when cleanup is delayed. Closed arrivals are rejected and counted; no coarse late-write path exists.

For a parent [p,e), advancement requires watermark-e >= max(source retention, source grace). It promotes every child group in that entire interval, then deletes all children. Retention is a minimum detail age: waiting for the whole parent can keep some children up to an additional parent width. Every higher-tier promotion also requires the corresponding lower-tier frontier to have reached e. Missing bucket rows do not prove completion. Empty prefixes advance in one range operation; populated intervals and groups are visited without walking each second across sparse years.

With seconds retained 3600 seconds and minute parents, [12:00,12:01) cannot promote before 13:01. At 13:00:59.999999999 it stays in seconds; at 13:01 it may become one minute bucket per group. An event in second [12:00:30,12:00:31) with grace 120 is still rejected at exactly 12:02:31, even though its detail remains stored for another hour. Clock rollback never reopens that second.

Persisted frontiers identify a disjoint authoritative tier for each retained interval. Query responses describe those intervals in resolutions, with width_seconds and tier. resolution_seconds is the coarsest width present (zero with no retained coverage). A query across minute and second ownership may return both bands; it never adds a parent to its children. A boundary that would split any intersecting retained bucket is refused with ErrPartialBucket. This also applies to coarsened empty intervals and filters matching no groups. Initial collection and the currently active fine bucket may have partial recorder coverage inside their bucket; an aligned query still reports that limited coverage explicitly.

Final finite retention deletes complete final buckets once their end reaches the age cutoff and lower-tier progress proves completeness. Zero final retention means forever. Key reclamation checks references at every tier. Expiry leaves lifetime counters and original recorder start intact. Queries distinguish not_collected, expired, not_observed_yet and covered emptiness. Expired-only statistics are null; retained empty count/sum are zero. Partial availability has complete=false and includes only available state. Neither an old schema nor an absent dimension is reconstructed; only immutable initial definitions are currently supported.

Deletion makes space reusable inside SQLite; it does not guarantee the live main file immediately shrinks. Snapshot exports compact retained state to a new standalone file. One Advance transaction can span the entire backlog and lock the handle for its duration. Context cancellation rolls back uncommitted work. Work pagination and automatic scheduling are deferred. SQL failure injection verifies rollback through every publication stage, and restart/snapshot/copy tests verify committed state and idempotent reruns. These checks are not a forced-process-crash or physical power-loss test; those remain release-hardening work.

## Recorded small demonstration

Run `go run ./examples/retention -n 20000`. It creates temporary files, ingests deterministic skewed values into 120 second buckets for one group, then jumps the explicit clock five years. Four tiers (second, minute, hour, day) fold those rows into one daily bucket. It queries, snapshots, copies that one file to a different directory, reopens it and checks identical exact state and persisted sketch estimates. A repeated Advance performs no additional promotion or expiry. One final stored sketch can be compared identically; multi-bucket query merges may randomly recompact.

The recorded docs/retention-session-4.json run used 1,602,117 bytes of newline-delimited serialized observation input, a 299,008-byte fine snapshot and a 53,248-byte retained snapshot including metadata/indexes. That is about 30.09:1 input-to-retained and 5.62:1 fine-to-retained for this fixture. Maximum observed requested-rank discrepancy was 0.0022 against the K=200 empirical model of approximately 0.0132947575. Its p99 value error was about 4.83%. The report includes individual rank intervals, absolute/relative value errors and exact aggregate results next to sizes.

The fixture has two minutes of input followed by idle time, not five years of continuous telemetry. It excludes WAL, peak working/export disk, reference memory and throughput measurements. It does not establish a 99% confidence guarantee or predict savings for arbitrary cardinality or time density. Inputs are deterministic; KLL compaction and measured point estimates can vary between runs. Broader volume, cardinality and continuous-history measurements belong to Session 5.
