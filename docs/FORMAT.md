# File format, revision 4

Status: pre-release. Session 4 stores metadata, immutable initial stream definitions, exact aggregate buckets, optional KLL distribution state, dimension groups, ingestion runtime state and retention frontiers. It does not store raw observations.

The SQLite application_id is 0x524c4442 (ASCII RLDB) and user_version is 4. Schema revision and executable release are independent. Open checks identity and version and refuses unknown or legacy versions without migration. Migrate explicitly upgrades revision 1, 2 or 3 to 4, retaining identity, definitions and any existing exact state, times and counters. It executes the whole DDL chain and version change in one transaction; a failed upgrade leaves the source revision intact. Take a closed-file backup or a snapshot from the compatible old binary before upgrading.

store_meta remains the revision-1 STRICT table with singleton=1, file_id and created_at. file_id is 32 hex characters generated from sixteen random bytes; created_at is UTC RFC3339 with optional nanoseconds. Snapshots preserve both. File identity is provenance, not an exclusive process lock.

stream_definitions remains keyed by (name, version), with effective_at and validated definition_json. Only new version-1 definitions are exposed. Definition identity and schema revision are distinct: revision-4 files still contain stream-definition version 1. A new definition may optionally include sketch algorithm, encoding_version, K and M; a sketch-enabled definition must validate against the first supported codec. Effective timestamps are UTC and align to the coarsest width. Tier fields remain integer width_seconds, retain_seconds and grace_seconds. Zero final-tier retention explicitly means forever.

stream_runtime is keyed by (stream, version) and references stream_definitions. It stores nullable watermark_ns and coverage_start_ns, plus checked nonnegative int64 accepted, rejected_invalid, rejected_late and rejected_group_limit counters. Null coverage_start_ns means ingestion coverage has not been established; explicit Advance may set a watermark before the first batch. New streams and revision-1 migrations begin with zero counters and no coverage; revision-2 migrations preserve existing runtime state. A successful valid-envelope batch establishes or extends coverage and commits counters atomically with bucket updates. The watermark is inclusive and nondecreasing. Nanoseconds are signed integers; event and clock ranges are [1970,2200).

dimension_groups is keyed by (stream, version, tuple_key), references the stream definition and stores last_seen_ns for the latest accepted event time. tuple_key is the full JSON array of UTF-8 string values in declared dimension order. Empty-dimensional streams use []. Tuple encoding is collision-free for the decoded ordered string values and does not depend on Go map iteration order. Values are limited to 1024 bytes each and encoded tuples to 4096 bytes. Final expiry reclaims a key only when no buckets at any tier reference it.

buckets is keyed by (stream, version, tuple_key, tier, start_ns), references dimension_groups and has an additional time index on (stream, version, tier, start_ns). Ingestion writes tier 0; Advance writes higher tiers by merging whole finalized parent intervals. Width comes from the immutable definition. Numeric state is n INTEGER, and sum, sum_comp, min, max, mean and m2 REAL. n must be positive and m2 nonnegative. Application validation rejects nonfinite or unrepresentable state; SQLite constraints alone do not implement every numerical invariant. Zero-observation intervals need no bucket row; recorded coverage disambiguates them from uncollected history.

Revision 3 adds buckets.sketch BLOB, nullable. For exact-only streams the value stays null. For configured populated buckets it contains a 48-byte RollupDB envelope followed by the pinned DataSketches Go v0.2.0 float64 generic KLL compact payload. The envelope identifies RDKL magic, codec version, float64-KLL type, little-endian K/M settings, payload length and SHA-256 checksum. Immutable definition settings and envelope settings must match. Native serialization metadata, weighted count and extrema must also agree with exact state. See docs/SKETCHES.md for byte offsets, accepted native variants and bounded layout validation.

Ingestion updates groups, exact and sketch aggregate state, runtime times and counters in one transaction. Every affected bucket is accumulated in memory within the bounded batch before its final state is flushed. Public statistics are derived from this state, with only selected exact names exposed and quantiles requested separately. No raw-event table exists. Details of arithmetic and query coverage are in docs/API.md.

Migration does not backfill a sketch or alter historical definitions. Existing exact-only buckets cannot recover distributions from moments. Missing/incompatible bytes in a configured populated bucket are errors. Unknown envelope/native versions and settings must never be reinterpreted silently. Adding a new codec or definition transitions requires an explicit compatibility policy and, when the schema changes, a format revision and migration tests.

Revision 4 adds retention_frontiers, a STRICT table keyed by (stream,version,tier), with through_ns INTEGER NOT NULL CHECK(through_ns>=0), referencing stream_definitions. For each nonfinal tier this is the exclusive end of its contiguous promoted prefix; for the final tier it is the expired prefix. A forever final tier stays at the definition's effective time. A stream with no frontier rows is new/migrated and defaults every frontier to effective_at; the first successful Advance writes the complete set. A partially present set is refused. Frontiers are aligned to the next tier's width (final expiry to its own width), nonincreasing across tiers, and never move backward.

Authoritative ownership is tier 0 at [F0,infinity), intermediate tier i at [Fi,F(i-1)), and the final tier at [Ffinal,F(final-1)). For a one-tier stream the final/finest band is [F0,infinity). Recorded coverage intersects those bands; expired and never-collected prefixes stay distinct. Whole-parent insertion, child deletion, every frontier, key reclamation and watermark advancement commit in one transaction. Persisted frontiers include empty intervals; an absent bucket is not evidence of unprocessed work. See docs/RETENTION.md.

WAL and shared-memory sidecars are operational files, not required companions of a completed snapshot. VACUUM INTO exports a compact consistent database and the wrapper syncs that output. Publication is not atomic; interrupted output may be incomplete. The supported transfer object is a successfully completed snapshot. Do not remove live journals or copy the live main file alone. Future size reports must distinguish main-file bytes, sidecars, exported bytes and peak working disk use.
