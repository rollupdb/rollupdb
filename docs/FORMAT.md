# File format, revision 2

Status: pre-release. Session 2 stores metadata, immutable initial stream definitions, exact aggregate buckets, dimension groups and ingestion runtime state. It does not store raw observations, percentile sketches or retention frontiers.

The SQLite application_id is 0x524c4442 (ASCII RLDB) and user_version is 2. Schema revision and executable release are independent. Open checks identity and version and refuses unknown or legacy versions without migration. Migrate explicitly upgrades revision 1 to 2, retaining identity and definitions and adding empty runtime state. It executes DDL, runtime initialization and version change in one transaction. A failed upgrade leaves revision 1 intact. Take a closed-file backup or a snapshot from the compatible old binary before upgrading.

store_meta remains the revision-1 STRICT table with singleton=1, file_id and created_at. file_id is 32 hex characters generated from sixteen random bytes; created_at is UTC RFC3339 with optional nanoseconds. Snapshots preserve both. File identity is provenance, not an exclusive process lock.

stream_definitions remains keyed by (name, version), with effective_at and validated definition_json. Only new version-1 definitions are exposed. Definition identity and schema revision are distinct: revision-2 files still contain stream-definition version 1. Effective timestamps are normalized to UTC and align to the coarsest configured width. Tier fields are integer width_seconds, retain_seconds and grace_seconds. Zero final-tier retention explicitly means forever.

stream_runtime is keyed by (stream, version) and references stream_definitions. It stores nullable watermark_ns and coverage_start_ns, plus checked nonnegative int64 accepted, rejected_invalid, rejected_late and rejected_group_limit counters. Null times mean ingestion coverage has not been established. New streams and migrated streams begin with zero counters and no coverage. One successful valid-envelope batch establishes coverage and commits all counters atomically with bucket updates. The watermark is inclusive and nondecreasing. Nanoseconds are signed integers; event and clock ranges are restricted to [1970,2200).

dimension_groups is keyed by (stream, version, tuple_key), references the stream definition and stores last_seen_ns for the latest accepted event time. tuple_key is the full JSON array of UTF-8 string values in declared dimension order. Empty-dimensional streams use []. Tuple encoding is collision-free for the decoded ordered string values and does not depend on Go map iteration order. Values are limited to 1024 bytes each and encoded tuples to 4096 bytes. Keys are not reclaimed until expiry is implemented.

buckets is keyed by (stream, version, tuple_key, tier, start_ns), references dimension_groups and has an additional time index on (stream, version, tier, start_ns). Only tier 0 is currently written. Width comes from the immutable definition. Numeric state is n INTEGER, and sum, sum_comp, min, max, mean and m2 REAL. n must be positive and m2 nonnegative. Application validation rejects nonfinite or unrepresentable state; SQLite constraints alone do not implement every numerical invariant. Zero-observation intervals need no bucket row; recorded coverage disambiguates them from uncollected history.

Ingestion updates groups, aggregate rows, runtime times and counters in one transaction. Every affected bucket is accumulated in memory within the bounded batch before its final state is flushed. Public statistics are derived from this stored state, with only selected names exposed. No raw-event table exists. Details of compensation, variance and query coverage are in docs/API.md.

Future sketch storage must record algorithm, encoding revision and parameters directly or by immutable reference. Unknown or incompatible payloads must be rejected; supported parameter-size merges must disclose any weaker accuracy. Adding sketch fields, retention frontiers, expiry coverage or schema-version transitions requires an explicit format revision and migration tests, not silent revision-2 reinterpretation.

WAL and shared-memory sidecars are operational files, not required companions of a completed snapshot. VACUUM INTO exports a compact consistent database and the wrapper syncs that output. Publication is not atomic; interrupted output may be incomplete. The supported transfer object is a successfully completed snapshot. Do not remove live journals or copy the live main file alone. Future size reports must distinguish main-file bytes, sidecars, exported bytes and peak working disk use.
