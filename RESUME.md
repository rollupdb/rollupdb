## Engine and on-disk state

The Go library exposes Create/Open/Migrate/Close/Info, CreateStream/Stream, Ingest/Advance/Query/Status and Snapshot. WithClock supplies explicit replay/test time. Format revision remains 4; Session 5 changes transports and examples, not schema or engine semantics. Explicit Migrate supports revision 1/2/3 transactionally, preserving identity, definitions, exact state, sketch bytes and runtime. Open never silently initializes or upgrades. Only immutable initial definition version 1 is supported.

Exact state uses checked int64 count, compensated sum/extrema and Welford/Chan variance. Average is compensated sum/count. One serialized connection and handle mutex protect lifecycle and methods. Ingest accepts 1..10000 observations with canonical bounded dimensions, deterministic group admission, one clock sample, a persisted nondecreasing watermark, ordered outcomes and transactional lifetime counters. Invalid/late/group-cap rejections update neither exact nor sketch data. A retry is new input; there is no deduplication. No raw-event table exists.

KLL remains Apache DataSketches Go v0.2.0 float64 generic KLL, explicit algorithm=kll_float64, encoding_version=1, M=8 and K in [64,4096]. Only equal configurations merge. The RDKL envelope and bounded kll_format.go validator check layout/settings/count/extrema/checksum before the pinned decoder. Do not change dependency/codec assumptions without compatibility review. compactCapacity attribution and Apache license/notices remain under third_party/datasketches; original engine licensing is separate.

KLL compaction is randomized. One persisted sketch decoded directly is stable across restart/snapshot/copy. Multi-bucket query merges can vary in percentile points; compare their rank/value accuracy, not point equality. Never reseed global random sources or use private deterministic hooks. The K=200 approximately 0.0132947575 normalized-rank model is an empirical 99% maximum-error fit, not a deterministic bound or relative value-error guarantee. Tests use a broad four-times-model-plus-1/N regression threshold, not a claimed confidence validation.

Advance explicitly processes finest-to-coarsest in one transaction. Whole parent [p,e) is eligible when watermark-e >= max(source retain, source grace), with higher tiers also gated by lower-tier completion. Source/target changes, contiguous frontiers (including empties), final expiry, key reclamation and watermark commit together. Same-time reruns do no data work; clock rollback cannot reopen ingestion. Fine detail may live up to one extra parent width. Late input is never redirected into a coarse tier. Sparse empty years advance by ranges, not per second.

For nonfinal tiers frontier Fi means promoted through (exclusive); the final frontier means expired through, and forever retention keeps that empty prefix at effective_at. New/migrated streams with no frontier rows default to effective_at; first Advance persists a complete set. Partial, misaligned, out-of-range or nonmonotone sets are refused. Ownership is tier 0 [F0,infinity), intermediate i [Fi,F(i-1)), final [Ffinal,F(final-1)); one-tier streams [F0,infinity). Query intersects recorder coverage with these disjoint bands and never adds parent plus children. Resolution segments include empty retained time. Partial coarse cuts are refused even for empty filters/intervals. resolution_seconds is the maximum available width or zero with no available history.

Original recorder coverage stays separate from expiry. Missing reasons are not_collected, expired and not_observed_yet. Covered empty count/sum are zero; unavailable-only statistics are null. A partial request returns available state with complete=false. Expired-only configured quantiles say expired. Advance extends existing coverage but does not invent a collection start before the first batch. Coverage describes the recorder, not completeness of the source feed.

Storage remains modernc.org/sqlite v1.60.1/libc v1.77.1, WAL, synchronous FULL, one owning process and local filesystem. Deletion reuses pages; Snapshot compacts via VACUUM INTO and syncs output. ## Session 5 interfaces

The CLI supports init/migrate/inspect/snapshot/create-stream/stream/stats/ingest/query/advance plus ingest-ndjson FILE STREAM INPUT [--batch-size N] and serve FILE [--listen 127.0.0.1:7070]. Existing JSON batch input remains bounded at 64 MiB, definitions/queries at 1 MiB. Shared transport.DecodeObject checks UTF-8, top-level object, unknown fields and trailing input; encoding/json duplicate keys retain last-value semantics.

NDJSON uses one Observation per physical LF/CRLF line; final unterminated lines are accepted and blanks/BOM/null/malformed/unknown/invalid UTF-8 are refused. Records cap at 256 KiB; batches default 1000, max 10000, and buffered serialized input caps at 8 MiB. These are input bounds, not process memory guarantees. A post-commit receipt contains line range and BatchResult. The terminal summary distinguishes committed records/batches/counters, next_line, failed_line, parsed-but-discarded records and submitted-but-unacknowledged records. Earlier batches survive failure. committed_records includes committed rejection outcomes. Pending input is not submitted on parse/read errors. A commit or receipt delivery failure can be ambiguous: do not replay blindly. The CLI closes its owned file/stdin reader on cancellation to unblock I/O; reusable ImportNDJSON callers own their readers.

The HTTP CLI accepts literal loopback addresses only, including optional free port 0, and opens an existing current-format database. It has no authentication/TLS/public bind mode and is for trusted local processes. Host must be localhost/loopback; Origin requests are refused; no CORS. Exported NewHandler must also be placed on a loopback listener by the caller. JSON POST bodies require application/json, uncompressed UTF-8 objects and no query parameters/noncanonical paths. HTTP NDJSON, remote authentication and arbitrary filesystem destinations are not exposed. JSON error codes/statuses are documented in docs/INTERFACES.md; internal storage errors do not expose SQL/paths.

Server timeouts are header 5s, full read 30s, write/idle 60s, maximum headers 16 KiB; engine contexts have 30s deadlines. The handler does not send early write success. Missing responses are not rollback proof. SIGINT/SIGTERM cancel active contexts and initiate ten-second graceful shutdown before force closing connections. Serve never closes a caller-owned DB; the CLI closes its handle after Serve returns. Keep it as the single file owner and call HTTP while running rather than another writer CLI.
